1. Základné pojmy

›
  • Databáza — zbierka previazaných údajov bez zbytočnej redundancie. Cieľ: vyhnúť sa anomáliám (vkladania, aktualizácie, mazania).
  • SRBD / DBMS — softvér nad OS, ktorý umožňuje prístup, uchovávanie, aktualizáciu, zálohy a zabezpečenie.
  • CRUD — Create, Read, Update, Delete.
  • SQL kategórie — DDL (CREATE/ALTER/DROP), DML (SELECT/INSERT/UPDATE/DELETE), DCL/TCL (GRANT/COMMIT).

Anomálie pri zlom návrhu

  • Vkladania — nemôžem evidovať X bez Y (napr. internát bez študenta)
  • Aktualizácie — zmena údaja vyžaduje úpravu vo viacerých riadkoch → nekonzistencia
  • Mazania — zmazaním záznamu stratím aj iné informácie

Funkčná závislosť

A → B = pre každú hodnotu A existuje práve jedna hodnota B. Príklady: id_pouzivatela → meno, mesto → PSC, funkcia → plat.

4. ERA modelovanie a kardinalita

›

Úrovne

  1. Konceptuálny — entity a vzťahy (vysoká abstrakcia)
  2. Logický — + atribúty
  3. Fyzický — tabuľky, dátové typy v konkrétnej DB

Základné pojmy

  • Entita → tabuľka
  • Atribút → stĺpec
  • Vzťah (relácia) → prepojenie entít

Kardinalita (maximum)

  • 1:1 — osoba↔občiansky preukaz. V DB: jedna tabuľka alebo FK.
  • 1:N — čitateľ↔knihy. FK na strane "N".
  • M:N — študent↔predmety, film↔herci. Vyžaduje prepojovaciu tabuľku s 2 FK!

Modalita (minimum)

0 = nepovinný, 1 = povinný. Zápis (min, max). POZOR: zapisuje sa na opačnú stranu, než ktorej entity sa týka.

Crow's Foot symboly

  • | — presne jeden (povinný)
  • o — nula (nepovinný)
  • < — viac
  • |< — 1..N (jeden alebo viac)
  • o< — 0..N (nula alebo viac)

5. Normalizácia (1NF, 2NF, 3NF)

›
Cieľ: efektívne organizovať údaje, eliminovať redundanciu, zachovať integritu. V praxi sa normalizuje do 3NF.

1NF — Prvá normálna forma

  1. Tabuľka má PK
  2. Každý atribút má atomické hodnoty (nedeliteľné)
  3. Žiadne opakujúce sa atribúty (typu kurz1, kurz2, kurz3)

Porušenia: zoznam v bunke "100, 105, 102"; stĺpce telefon1/telefon2/telefon3; neatomické "adresa" obsahujúca ulicu+mesto.

2NF — Druhá normálna forma

  1. Je v 1NF
  2. Každý nekľúčový atribút je úplne funkčne závislý od CELÉHO PK

Problém vzniká len pri zložených PK. Ak časť atribútov závisí len od časti PK, treba ich vyčleniť.

Príklad: Hodnotenie(student PK, kod_predmetu PK, nazov_predmetu, znamka) — nazov_predmetu závisí len od kod_predmetu. Riešenie: oddeliť tabuľku Predmety.

3NF — Tretia normálna forma

  1. Je v 2NF
  2. Žiadny nekľúčový atribút nie je tranzitívne závislý od PK

Tranzitívna závislosť: PK → A → B, kde A aj B sú nekľúčové.

Príklad: Zam(rc, meno, mesto, PSC, funkcia, plat) — mesto → PSC a funkcia → plat. Riešenie: oddeliť tabuľky Mesto a Funkcia.

Denormalizácia

  • Opačný proces — zámerné pridanie redundancie
  • Cieľ: zrýchliť SELECT, znížiť počet JOIN-ov
  • Cena: duplicita, riziko nekonzistencie, zložitejšie INSERT/UPDATE

6. SQL — najdôležitejšie príkazy

›

DDL — CREATE / ALTER / DROP

CREATE TABLE Zamestnanci (
    id INT AUTO_INCREMENT PRIMARY KEY,
    meno VARCHAR(50) NOT NULL,
    plat DECIMAL(8,2) DEFAULT 0,
    id_oddelenie INT,
    FOREIGN KEY (id_oddelenie) REFERENCES Oddelenia(id)
        ON DELETE SET NULL ON UPDATE CASCADE
);

ALTER TABLE Zamestnanci ADD COLUMN email VARCHAR(100) UNIQUE;
ALTER TABLE Zamestnanci MODIFY COLUMN meno VARCHAR(100);
ALTER TABLE Zamestnanci DROP COLUMN plat;

DROP TABLE Zamestnanci;

Constraints

NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, CHECK, DEFAULT, AUTO_INCREMENT

FK akcie

  • CASCADE — prepíše do závislých
  • SET NULL — nastaví NULL
  • RESTRICT / NO ACTION — zakáže operáciu

DML — INSERT / UPDATE / DELETE

INSERT INTO Zamestnanci (meno, plat) VALUES ('Jano', 1200.00);
UPDATE Zamestnanci SET plat = plat * 1.10 WHERE id_oddelenie = 1;
DELETE FROM Zamestnanci WHERE id = 5;
TRUNCATE TABLE Zamestnanci; -- rýchle, resetuje AUTO_INCREMENT, nedá sa rollbackovať

SELECT — kompletná štruktúra

SELECT [DISTINCT] stlpce
FROM tabulka
[JOIN ...]
[WHERE podmienka]
[GROUP BY stlpce]
[HAVING podmienka_na_skupiny]
[ORDER BY stlpce ASC|DESC]
[LIMIT pocet OFFSET start];

Logické poradie vykonania

FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

WHERE vs HAVING: WHERE filtruje riadky pred zoskupením, HAVING filtruje skupiny po GROUP BY (môže obsahovať agregačné funkcie).

Operátory

  • Porovnávanie: =, <>, <, >, <=, >=
  • Logické: AND, OR, NOT
  • Rozsah: BETWEEN x AND y
  • Množina: IN (a, b, c)
  • Vzor: LIKE 'A%' (% = ľubovoľne, _ = 1 znak)
  • NULL: IS NULL / IS NOT NULL (nie =NULL!)

Agregačné funkcie

COUNT, SUM, AVG, MIN, MAX

SELECT id_oddelenie, COUNT(*) AS pocet, AVG(plat) AS priemer
FROM Zamestnanci
WHERE plat > 500
GROUP BY id_oddelenie
HAVING AVG(plat) > 1000;

JOIN typy

TypVýznam
INNER JOINiba zhody v oboch tabuľkách
LEFT JOINvšetko z ľavej + zhody z pravej (chýbajúce = NULL)
RIGHT JOINvšetko z pravej + zhody z ľavej
FULL JOINvšetko z oboch (v MySQL cez UNION)
CROSS JOINkartézsky súčin
SELF JOINtabuľka so sebou
SELECT z.meno, o.nazov
FROM Zamestnanci z
INNER JOIN Oddelenia o ON z.id_oddelenie = o.id;

VIEW (pohľad)

CREATE VIEW v_top_platy AS
SELECT meno, plat FROM Zamestnanci WHERE plat > 2000;

Virtuálna tabuľka — zjednodušuje opakované dotazy, skrýva komplexnosť, zvyšuje bezpečnosť.

INDEX

CREATE INDEX idx_meno ON Zamestnanci(meno);
CREATE UNIQUE INDEX idx_email ON Zamestnanci(email);

Zrýchľuje SELECT/WHERE/JOIN, ale spomaľuje INSERT/UPDATE/DELETE. PK má index automaticky.

TRANSAKCIE — ACID

  • Atomicity — buď celé alebo nič
  • Consistency — DB ostane v konzistentnom stave
  • Isolation — paralelné transakcie sa neovplyvňujú
  • Durability — po COMMIT-e zmeny trvajú aj po zlyhaní
START TRANSACTION;
UPDATE Ucty SET zostatok = zostatok - 100 WHERE id = 1;
UPDATE Ucty SET zostatok = zostatok + 100 WHERE id = 2;
COMMIT; -- alebo ROLLBACK

Izolačné úrovne: READ UNCOMMITTED → READ COMMITTED → REPEATABLE READ → SERIALIZABLE

Problémy: dirty read, non-repeatable read, phantom read

Zámky (LOCKS)

  • Shared (S) — pre čítanie, viacero transakcií súčasne
  • Exclusive (X) — pre zápis, len jedna transakcia
  • Deadlock — vzájomné čakanie, DBMS jednu transakciu zruší

TRIGGER

CREATE TRIGGER pred_insert
BEFORE INSERT ON Zamestnanci
FOR EACH ROW
SET NEW.datum_vytvorenia = NOW();

Časy: BEFORE/AFTER · Udalosti: INSERT/UPDATE/DELETE · Pseudo-tabuľky: NEW, OLD

PROCEDURE vs FUNCTION

  • Procedure — volá sa cez CALL, nemusí vracať hodnotu
  • Function — vracia hodnotu, dá sa použiť v SELECT
CREATE PROCEDURE zvys_plat(IN id_z INT, IN o DECIMAL(5,2))
BEGIN
    UPDATE Zamestnanci SET plat = plat + o WHERE id = id_z;
END;
CALL zvys_plat(1, 100.00);

USERS

CREATE USER 'jano'@'localhost' IDENTIFIED BY 'heslo';
GRANT SELECT, INSERT ON db.* TO 'jano'@'localhost';
REVOKE INSERT ON db.* FROM 'jano'@'localhost';
DROP USER 'jano'@'localhost';

SHOW

SHOW DATABASES;
SHOW TABLES;
SHOW COLUMNS FROM Zamestnanci;
DESCRIBE Zamestnanci;
SHOW CREATE TABLE Zamestnanci;
SHOW INDEX FROM Zamestnanci;

9. Stavebné prvky HMI

›
  • Premenné (tags) — externé (z PLC) / interné (len HMI). Vytváranie: manuálne / import / linkovaním
  • Obrazovky — Base (technologická) / Master/Template (spoločné prvky) / Popup (pomocné okná)
  • Grafické objekty — texty, tlačidlá, indikátory, symboly (motory, ventily, nádrže), animácie
  • Alarmy — binárne / analógové (limity HI, LO, HIHI, LOLO)
  • Trendy — online (real-time) / historické
  • Recepty — uložené sady technologických parametrov

Alarmy — informácie

  • Dátum a čas vzniku
  • Alarmová správa
  • Názov a hodnota premennej
  • Priorita (severity)
  • Operátor ktorý alarm potvrdil

Stavy alarmu: aktívny / zaniknutý / potvrdený (ACK)

Recepty — operácie

  • Send — odoslať parametre receptu do PLC
  • Snapshot — načítať aktuálne hodnoty z PLC do receptu
  • Save — uložiť do úložiska HMI
  • Delete — odstrániť

10. Návrh HMI — ergonómia a farby

›
HMI tvorí 50–75 % nákladov riadiaceho systému.

ISO 9241 — ergonómia interakcie

Definuje 3 vlastnosti použiteľnosti (usability):

  1. Účinnosť (effectiveness) — splní používateľ úlohu?
  2. Efektívnosť (efficiency) — rýchlo a s minimom úsilia?
  3. Spokojnosť (satisfaction) — prirodzená práca bez stresu?

3 kroky práce operátora

  1. Detekcia — zistiť že nastala zmena (farba, blikanie, alarm, zvuk)
  2. Pochopenie — interpretovať info (jasné symboly, štandardné farby)
  3. Reakcia — vykonať zásah

Rozdelenie obrazovky (3 oblasti)

ČasťObsah
Prehľadová (information area)hlavička, čas, alarmy
Pracovná (work area)schéma procesu, trendy
Ovládacia (control area)navigácia, tlačidlá

Prehľadová a ovládacia časť bývajú v šablóne (template).

12. SCADA systémy

›

Definícia

SCADA = Supervisory Control And Data Acquisition. Systém pre dohľad a riadenie geograficky rozložených procesov (telecontrol system).

Aplikácie: energetické siete, vodárne, ropovody/plynovody, doprava, veľké závody.

SCADA vs DCS

Architektúra SCADA

  1. Senzory a akčné členy (field level)
  2. PLC / RTU — lokálne riadenie
  3. Komunikačná sieť
  4. SCADA server — agregácia dát
  5. Historian — historická databáza
  6. Operátorské pracoviská

RTU (Remote Terminal Unit)

Zariadenie pre vzdialený zber dát a komunikáciu so SCADA.

Vlastnosti: robustná konštrukcia, RTC, zálohované napájanie (UPS/batéria), lokálna pamäť, watchdog, redundantné porty.

Protokoly: Modbus, IEC 60870-5-101/104, DNP3, IEC 61850.

4 generácie SCADA

  1. Centralizované — sálové počítače, proprietárne protokoly
  2. Distribuované — LAN, viac staníc
  3. Sieťové — TCP/IP, WAN, škálovateľnosť
  4. Moderné — Internet, cloud, IoT, otvorené protokoly

Redundancia

Redundantné servery, databázy (historian), komunikačné trasy, operátorské stanice, UPS napájanie.

Distribuovaná architektúra — komponenty

  • I/O server — komunikácia s PLC/RTU
  • Alarm server — spracovanie alarmov
  • Historian server — archivácia
  • SCADA server — distribúcia dát klientom
  • Operátorské stanice

Vývoj HMI obrazoviek

  • 80. roky: mimic displays s fyzickými tlačidlami
  • 90. roky: farebné grafické (často preplnené)
  • 2010+: High Performance HMI — minimalistické, prehľadné, farby len pre alarmy

13. P&ID symbolika — ISO 3511 / ANSI/ISA-5.1

›

P&ID = Piping and Instrumentation Diagram. Hlavné normy:

  • ISO 3511 (Európa)
  • ANSI/ISA-5.1 (USA, procesný/petro priemysel)

Základná značka prístroja

Kružnica (~10 mm) s písmenkovým kódom.

Umiestnenie:

  • Bez čiary — v technológii (field)
  • 1 čiara — dostupný operátorovi (panel, HMI)
  • 2 čiary — pomocný panel / za panelom

Štruktúra písmenkového kódu

  1. 1. písmeno — veličina (T, P, F, L...)
  2. 2. písmeno (voliteľné) — dodatok (D, F, J, Q)
  3. Ďalšie písmená — funkcia (poradie I-R-C-T-Q-S-Z-A)

Symboly v schéme

  • Hrubá čiara — technologické zariadenia / potrubie
  • Tenká čiara — pripojenie snímača / signál
  • Bodka na križovaní = spojenie; bez bodky = len križujú sa
  • Trojuholník — korekčný člen
  • Motýlik (kosoštvorec) — regulačný ventil
  • Šesťhran — riadiaci počítač (PLC/DCS)
  • Štvorec s kruhom — zdieľané zobrazenie/riadenie (DCS, SCADA HMI)

Správanie ventilu pri výpadku

  • Šípka nahor = fail OPEN (otvorí)
  • Šípka nadol = fail CLOSE (zatvorí)
  • Dve čiarky = fail FREEZE (zostane v polohe)

Typy ventilov

  • Gate valve (šupátkový) — len úplne OTV / ZATV, nie na reguláciu
  • Globe valve (sedlový) — plynulá regulácia prietoku

Druhy signálov

  • Elektrický — čiarky cez čiaru
  • Pneumatický — šípka
  • Hydraulický — vlnka / "L"

Databázy — možné skúšobné otázky
Q1.Vysvetlite pojem normalizácia, prečo sa robí a aké sú jej formy do 3NF.›

Normalizácia je proces efektívnej organizácie údajov v databáze. Cieľmi sú: eliminácia redundancie, zabezpečenie integrity dát, vyhnutie sa anomáliám (vkladania, aktualizácie, mazania).

Bezstratová dekompozícia = pri spätnom spojení rozdelených tabuliek sa nesmú stratiť žiadne údaje.

1NF: tabuľka má PK, každý atribút obsahuje atomické hodnoty, žiadne opakujúce sa atribúty.

2NF: je v 1NF + každý nekľúčový atribút úplne funkčne závisí od CELÉHO PK (problém vzniká pri zložených PK).

3NF: je v 2NF + žiaden nekľúčový atribút nie je tranzitívne závislý od PK.

Q2.Aké sú typy databázových kľúčov? Definujte aspoň 5.›
  • Primary key (PK) — jednoznačne identifikuje riadok, neopakujúce sa hodnoty, NEsmie obsahovať NULL.
  • Foreign key (FK/CK) — stĺpec(ce) odkazujúce na PK/UNIQUE inej tabuľky, vytvára relácie, zabezpečuje referenčnú integritu.
  • Candidate key — minimálna množina atribútov ktorá jednoznačne identifikuje riadky. Z kandidátnych kľúčov je vybraný jeden ako PK.
  • Superkey — množina atribútov ktorá identifikuje riadky (nemusí byť minimálna).
  • Alternate key — kandidátny kľúč ktorý NEbol zvolený za PK. Jedinečnosť cez UNIQUE.
  • Surrogate key — umelo vytvorený identifikátor bez vlastného významu (napr. AUTO_INCREMENT id).
  • Natural key — kľúč z reálnych atribútov entity (napr. rodné číslo).
  • Composite key — kľúč tvorený kombináciou viacerých stĺpcov.
  • Intelligent key — kľúč ktorého jednotlivé časti nesú vlastný význam.
Q3.Mám tabuľku Studenti(rc, meno, mesto, PSC, hobby1, hobby2, hobby3). V akej je NF a ako by ste ju normalizovali do 3NF?›

Aktuálny stav: nie je v 1NF — tabuľka má opakujúce sa atribúty (hobby1, hobby2, hobby3).

Krok 1 — do 1NF: oddeliť koníčky do samostatnej tabuľky a vytvoriť PK:

Studenti(rc PK, meno, mesto, PSC)
StudentHobby(id PK, rc FK, hobby)

Krok 2 — do 2NF: 2NF je už splnená — tabuľka má jednoduchý PK, takže nekľúčové atribúty nemôžu závisieť len od časti PK.

Krok 3 — do 3NF: v tabuľke Studenti existuje tranzitívna závislosť rc → mesto → PSC. Oddelíme:

Studenti(rc PK, meno, mesto_id FK)
Mesto(mesto_id PK, mesto, PSC)
StudentHobby(id PK, rc FK, hobby)
Q4.Vysvetlite pojem ACID v transakciách.›
  • Atomicity (atomickosť) — transakcia sa vykoná buď celá alebo vôbec. Ak zlyhá v polovici, urobí sa ROLLBACK.
  • Consistency (konzistencia) — transakcia prevedie DB z jedného konzistentného stavu do druhého. Dodržiavajú sa všetky constrainty.
  • Isolation (izolácia) — paralelne bežiace transakcie sa neovplyvňujú. Implementuje sa pomocou izolačných úrovní a zámkov.
  • Durability (trvácnosť) — po úspešnom COMMIT-e zmeny trvajú aj v prípade výpadku systému (zápis na disk).

Príkazy: START TRANSACTION / COMMIT / ROLLBACK.

Q5.Aký je rozdiel medzi WHERE a HAVING v SQL?›

WHERE filtruje jednotlivé riadky pred zoskupením (GROUP BY). Nemôže obsahovať agregačné funkcie.

HAVING filtruje skupiny po GROUP BY. Môže obsahovať agregačné funkcie (COUNT, SUM, AVG...).

SELECT id_oddelenie, AVG(plat) AS priemer
FROM Zamestnanci
WHERE plat > 500          -- filter na riadky
GROUP BY id_oddelenie
HAVING AVG(plat) > 1000;   -- filter na skupiny

Logické poradie: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.

Q6.Vysvetlite rozdiel medzi INNER, LEFT, RIGHT a CROSS JOIN.›
  • INNER JOIN — vráti iba riadky, ktoré majú zhodu v OBOCH tabuľkách.
  • LEFT JOIN (LEFT OUTER) — vráti VŠETKO z ľavej tabuľky + zhody z pravej. Chýbajúce hodnoty z pravej sú NULL.
  • RIGHT JOIN — vráti všetko z pravej + zhody z ľavej.
  • CROSS JOIN — kartézsky súčin: každý riadok ľavej tabuľky s každým riadkom pravej (počet riadkov = m × n).
SELECT z.meno, o.nazov
FROM Zamestnanci z
LEFT JOIN Oddelenia o ON z.id_oddelenie = o.id;
Q7.Čo je VIEW, na čo slúži a v čom sa líši od tabuľky?›

VIEW (pohľad) je virtuálna tabuľka definovaná SELECT dopytom. Nemá vlastné fyzické dáta — pri každom dopyte sa vyhodnotí definícia.

Výhody: zjednodušuje opakované zložité dotazy, skrýva komplexnosť pred používateľmi, zvyšuje bezpečnosť (môžem dať prístup len k view bez prístupu k tabuľke).

CREATE VIEW v_top_platy AS
SELECT meno, plat FROM Zamestnanci WHERE plat > 2000;

SELECT * FROM v_top_platy; -- ako z tabuľky
DROP VIEW v_top_platy;

Hlavný rozdiel od tabuľky: view neukladá dáta, je len uloženým dopytom.

Q8.Vysvetlite pojem INDEX, jeho výhody a nevýhody.›

INDEX je dátová štruktúra (typicky B-strom) ktorá zrýchľuje vyhľadávanie v tabuľke.

Výhody:

  • Zrýchľuje SELECT, WHERE, ORDER BY, JOIN na indexovaných stĺpcoch.
  • UNIQUE index vynucuje jedinečnosť.
  • PK má automaticky unique index.

Nevýhody:

  • Spomaľuje INSERT/UPDATE/DELETE (musí sa aktualizovať aj index).
  • Zaberá miesto na disku.
CREATE INDEX idx_meno ON Zamestnanci(meno);
CREATE UNIQUE INDEX idx_email ON Zamestnanci(email);
DROP INDEX idx_meno ON Zamestnanci;
Q9.Vysvetlite kardinalitu vzťahov a ako sa rieši M:N v relačnej databáze.›

Kardinalita určuje maximálny počet výskytov objektov jednej entity priradených k druhej.

  • 1:1 — každej entite zodpovedá najviac jedna entita na druhej strane (osoba↔občiansky preukaz). V DB: jedna tabuľka alebo FK s UNIQUE.
  • 1:N — jednému riadku v prvej tabuľke zodpovedá viacero v druhej, ale jednému v druhej len jeden v prvej (čitateľ↔knihy). V DB: FK na strane "N".
  • M:N — viacerým v prvej zodpovedá viacero v druhej a opačne (študent↔predmety, film↔herci).

Riešenie M:N: nedá sa uložiť priamo medzi dvomi tabuľkami. Vytvorí sa prepojovacia (väzobná) tabuľka s dvoma FK na obe entity.

Studenti(id PK, meno)
Predmety(id PK, nazov)
StudentPredmet(id_student FK, id_predmet FK, znamka,
    PRIMARY KEY(id_student, id_predmet))
Q10.Čo je TRIGGER a ako sa používa? Daj príklad.›

TRIGGER (spúšťač) je procedúra automaticky spustená DBMS pri INSERT/UPDATE/DELETE na tabuľke.

Časy spustenia: BEFORE / AFTER.
Udalosti: INSERT / UPDATE / DELETE.
Pseudo-tabuľky: NEW (nová hodnota), OLD (pôvodná hodnota).

Príklad — automatické nastavenie dátumu vytvorenia:

CREATE TRIGGER pred_insert
BEFORE INSERT ON Zamestnanci
FOR EACH ROW
SET NEW.datum_vytvorenia = NOW();

Príklad — log zmien platov:

CREATE TRIGGER log_plat
AFTER UPDATE ON Zamestnanci
FOR EACH ROW
INSERT INTO PlatLog(id_zam, stary_plat, novy_plat, datum)
VALUES (OLD.id, OLD.plat, NEW.plat, NOW());
Q11.Aké sú anomálie pri zlej štruktúre databázy?›

Pri zle navrhnutej DB s duplicitnými údajmi môžu vznikať 3 typy anomálií:

  • Anomália vkladania — nemožno evidovať jednu entitu bez druhej. Napr. nemôžem evidovať nový internát, kým nemám aspoň jedného študenta v ňom.
  • Anomália aktualizácie — zmena údaja musí byť vykonaná vo všetkých riadkoch. Ak sa niektorý riadok neaktualizuje, vzniká nekonzistencia.
  • Anomália mazania — vymazaním záznamu stratím aj iné informácie. Napr. zmazaním posledného študenta na internáte stratím aj informáciu o telefónnom čísle internátu.

Riešením je normalizácia — rozdelenie do viacerých tabuliek prepojených cez FK.

Vizualizácia — možné skúšobné otázky
Q13.Aké sú hlavné úlohy vizualizácie v priemyselných riadiacich systémoch?›

Vizualizácia (HMI/SCADA) predstavuje rozhranie medzi riadiacim systémom a človekom. Úlohy:

  • Monitoring procesu — prehľadné zobrazenie stavu zariadení a meraných veličín v reálnom čase.
  • Ovládanie procesu — nastavovanie parametrov, žiadaných hodnôt, štart/stop, AUTO/MAN režimy.
  • Signalizácia porúch / alarmy — upozornenia na neštandardné stavy.
  • Diagnostika a údržba — informácie o stave zariadení a komunikácie.
  • Archivácia dát — záznam histórie pre analýzu a diagnostiku.
  • Trendy — sledovanie vývoja veličín v čase.

Vizualizácia premieňa interné dáta riadiaceho systému na informácie zrozumiteľné pre človeka.

Q14.Vymenuj a popíš základné stavebné prvky HMI projektu.›
  • Premenné (tags) — reprezentujú procesné veličiny a stavy. Externé (z PLC) alebo interné (len HMI).
  • Obrazovky — Base (technologická), Master/Template (spoločné prvky — hlavička, navigácia), Popup (pomocné okná pre ovládanie).
  • Grafické objekty — texty, číselné zobrazenia, tlačidlá, indikátory, grafické symboly (motory, ventily, nádrže), animácie.
  • Alarmy — binárne (diskrétny stav) alebo analógové (prekročenie limitov HI, LO, HIHI, LOLO).
  • Trendy — online (real-time) alebo historické (archivované).
  • Recepty — uložené sady technologických parametrov pre konkrétny výrobok.
  • Používateľské prístupy — rôzne úrovne oprávnení.
  • Jazykové verzie.
Q15.Vysvetlite rozdiel medzi HMI, SCADA a DCS.›

HMI (Human-Machine Interface) — rozhranie medzi človekom a strojom. Lokálne ovládanie a monitoring jedného zariadenia alebo výrobnej linky (operátorský panel, dotykový displej).

SCADA (Supervisory Control And Data Acquisition) — systém pre dohľad a riadenie geograficky rozložených procesov (telecontrol). Centrálne monitorovanie distribuovaných zariadení (vodárne, ropovody, energetické siete, doprava). Komunikuje s PLC/RTU cez WAN.

DCS (Distributed Control System) — systém pre riadenie technologických procesov v rámci jedného závodu. Distribuované riadenie realizované priamo v riadiacich staniciach systému. Typické pre chémiu, petrochémiu, energetické bloky.

Hlavný rozdiel: HMI je lokálne, SCADA je rozsiahla a geograficky distribuovaná, DCS je integrovaná v jednom závode.

Q16.Aké sú vlastnosti RTU a v čom sa líši od PLC?›

RTU (Remote Terminal Unit) je zariadenie pre zber dát z technologického procesu a komunikáciu so SCADA systémom.

Funkcie RTU: pripojenie senzorov/akčných členov, zber a spracovanie údajov, prenos do SCADA, prijímanie povelov. RTU môže vykonávať aj lokálne riadenie.

Vlastnosti RTU:

  • Robustná konštrukcia, odolnosť voči teplote a vlhkosti
  • Hodiny reálneho času (RTC) pre časové značky údajov
  • Zálohované napájanie (UPS/batéria)
  • Lokálna pamäť pre prípad výpadku komunikácie
  • Watchdog (automatický reštart pri chybe)
  • Redundantné komunikačné porty
  • Protokoly: Modbus, IEC 60870-5-101/104, DNP3, IEC 61850

Rozdiel od PLC: PLC je optimalizované pre rýchle real-time riadenie v rámci závodu. RTU je optimalizované pre telemetriu a vzdialené geograficky rozložené aplikácie, má vstavané RTC a zálohované napájanie.

Q17.Vysvetlite 3 vlastnosti použiteľnosti podľa ISO 9241.›

Norma ISO 9241 sa zaoberá ergonómiou interakcie človek-počítač. Definuje tri vlastnosti použiteľnosti (usability):

  • Účinnosť (effectiveness) — dokáže používateľ pomocou systému splniť požadovanú úlohu? Ide o správnosť a úplnosť splnenia cieľa.
  • Efektívnosť (efficiency) — dokáže používateľ vykonať úlohu rýchlo a s minimálnym úsilím alebo chybami? Vzťah medzi výsledkom a vynaloženou energiou/časom.
  • Spokojnosť (satisfaction) — je práca so systémom prirodzená, prehľadná a bez zbytočného stresu?

Cieľom návrhu HMI je vytvoriť rozhranie, ktoré umožní operátorovi pracovať správne, rýchlo a s minimálnym úsilím.

Q19.Aké sú faktory výberu HMI zariadenia?›
  1. Prevádzkové prostredie — teplota, vlhkosť, prach, voda, vibrácie, krytie IP, EX prostredie (výbušné), elektromagnetické rušenie (EMI).
  2. Typ aplikácie a požiadavky používateľa — počet zobrazovaných veličín, trendy, archivácia, počet obrazoviek, výkon, veľkosť pamäte.
  3. Možnosti pripojenia — fyzické rozhrania (Ethernet, USB, SUB-D9/25), komunikačné protokoly (Modbus, Modbus TCP/IP, Profinet, EtherCAT), kompatibilita s riadiacim systémom.
  4. Spôsob zadávania údajov — dotykový displej / fyzické tlačidlá / kombinácia. Operátor v rukaviciach potrebuje fyzické tlačidlá alebo špeciálny dotykový displej.
  5. Programovací softvér — proprietárny vs otvorený, dostupnosť knižníc (tlačidlá, bargrafy, trendy, alarmové okná), kompatibilita s hardvérom.
  6. Ďalšie hľadiská — rozšíriteľnosť, technická podpora výrobcu, dokumentácia, cena.

Postup: najprv overiť, či zariadenie spĺňa technické požiadavky, až potom porovnávať cenu.

Q21.Aké sú typy alarmov v HMI a aké informácie sa pri alarme zobrazujú?›

Typy alarmov:

  • Binárne alarmy — viazané na diskrétne stavy (porucha motora, ventil zatvorený, hladina mimo rozsahu).
  • Analógové alarmy — prekročenie definovaných limitov hodnoty: HI, LO, HIHI, LOLO.

Informácie zobrazované pri alarme:

  • Dátum a čas vzniku alarmu
  • Alarmová správa (popis)
  • Názov a aktuálna hodnota premennej, ktorá alarm aktivuje
  • Priorita alarmu (severity)
  • Operátor, ktorý alarm potvrdil

Stavy alarmu: aktívny (porucha trvá) / zaniknutý (podmienka už neplatí) / potvrdený (ACK — operátor ho potvrdil).

Alarmy sa zvyčajne archivujú pre neskoršiu analýzu.

Q22.Vysvetli 4 generácie SCADA systémov.›
  1. 1. generácia — Centralizované SCADA: realizované na veľkých sálových počítačoch, proprietárne komunikačné protokoly, systémy neboli prepojené s inými sieťami.
  2. 2. generácia — Distribuované SCADA: spracovanie dát rozdelené medzi viacero staníc, komunikácia cez lokálne siete (LAN), stále prevažne proprietárne protokoly.
  3. 3. generácia — Sieťové SCADA: využitie štandardných sieťových technológií (TCP/IP), prepojenie cez LAN a WAN siete, lepšia škálovateľnosť veľkých systémov.
  4. 4. generácia — Moderné SCADA: využitie internetu, cloudových služieb a IoT, otvorené komunikačné protokoly, integrácia s databázami a analytickými nástrojmi.
Q23.Vysvetli rozdiel medzi gate valve a globe valve a čo znamenajú symboly fail open / fail close.›

Gate valve (šupátkový ventil) — slúži najmä na úplné otvorenie alebo úplné uzavretie prietoku. Nie je vhodný na reguláciu. V schéme je značený motýlikom bez bodky.

Globe valve (sedlový ventil) — umožňuje plynulú reguláciu prietoku. Používa sa v regulačných slučkách. V schéme je motýlik s bodkou v strede.

Správanie ventilu pri výpadku energie alebo signálu:

  • Šípka nahor (fail open) — pri výpadku ventil otvorí. Používa sa napr. pri bezpečnostných ventiloch, kde sa nesmie zabrániť úniku tlaku.
  • Šípka nadol (fail close) — pri výpadku ventil zatvorí. Používa sa napr. pri dávkovaní nebezpečných látok.
  • Dve čiarky (fail freeze / fail in place) — pri výpadku ventil zostane v aktuálnej polohe.

Voľba správania je dôležitá z hľadiska bezpečnosti technologického procesu.

Q24.Aké sú formy redundancie v SCADA systéme?›

Redundancia = systém obsahuje záložné komponenty, ktoré môžu prevziať funkciu pri zlyhaní primárnej časti. Zvyšuje dostupnosť a spoľahlivosť systému.

Typické formy redundancie v SCADA:

  • Redundantné SCADA servery — záložný server preberá funkciu pri výpadku hlavného (active/standby).
  • Redundantná databáza (historian) — zabezpečenie dostupnosti historických dát.
  • Redundantná komunikačná sieť — viacero komunikačných trás medzi zariadeniami.
  • Redundantné operátorské pracoviská — viacero operátorských staníc na sledovanie procesu.
  • Zálohované napájanie — UPS, dieselgenerátory.

Redundancia je kľúčová najmä v kritických infraštruktúrach (energetika, vodárne, doprava).

Q25.Vysvetli rozdelenie HMI obrazovky na 3 oblasti.›

Typické rozdelenie HMI obrazovky podľa odporúčaní VDI/VDE 3699 a ISA-101:

  1. Prehľadová časť (information area) — typicky hore. Obsahuje:
    • názov obrazovky, čas, stav systému
    • systémové a procesné hlásenia
    • často zobrazenie posledných alarmov
  2. Pracovná časť (work area) — stred obrazovky. Hlavná oblasť s:
    • technologickou schémou
    • zariadeniami, veličinami, stavmi
    • alarmovými/trendovými/receptovými oknami
  3. Ovládacia časť (control area) — typicky dole. Obsahuje:
    • navigáciu medzi obrazovkami
    • ovládacie tlačidlá alebo menu systému

Prehľadová a ovládacia časť bývajú definované v šablóne (template/master panel), ktorá je spoločná pre všetky obrazovky. Pracovná časť sa mení podľa aktuálnej obrazovky.

Kombinované — situačné otázky
Q26.Vo veľkej vodárenskej spoločnosti chcú monitorovať a riadiť čerpacie stanice rozmiestnené po celom kraji z jedného dispečerského pracoviska. Aký typ systému navrhnete a aké komponenty?›

Ide o klasickú aplikáciu pre SCADA systém (geograficky distribuované zariadenia).

Architektúra:

  • Na každej čerpacej stanici RTU alebo PLC s telemetriou (napr. Siemens CP1243-1).
  • RTU má vstavané hodiny reálneho času, zálohované napájanie (batéria/UPS) a lokálnu pamäť pre prípad výpadku komunikácie.
  • Komunikácia RTU → SCADA cez WAN (často mobilná sieť, optika alebo rádiový kanál).
  • Protokoly: Modbus TCP/IP, IEC 60870-5-104, DNP3.
  • Centrálny SCADA server agreguje dáta zo všetkých RTU.
  • Historian archivuje historické dáta pre analýzu.
  • Operátorské pracoviská v dispečingu — sledovanie + ovládanie z centra.
  • Redundancia: záložný SCADA server, redundantné komunikačné trasy, UPS, redundantné operátorské stanice.
Q27.Operátor v hlučnej hale pracuje s rukavicami. Aké HMI a aké prvky signalizácie navrhnete?›

HMI zariadenie:

  • Fyzické tlačidlá (lepšie ako dotykový displej v rukaviciach), prípadne priemyselný dotykový displej prispôsobený na ovládanie v rukaviciach.
  • Robustný operátorský panel s dostatočne veľkými tlačidlami.
  • Vyššie krytie IP (proti prachu/striekajúcej vode).

Signalizácia v hlučnom prostredí:

  • Silnejšia vizuálna signalizácia — signalizačné stĺpiky (červená/žltá/zelená), majáky pre alarmy.
  • Akustická signalizácia musí byť dostatočne hlasná, ale pri hluku je lepšie sa spoľahnúť na vizuál.
  • Farby podľa IEC 60204-1: červená = STOP/emergency, zelená = normál, žltá = varovanie.
Q28.Mám napísať SQL dotaz: pre každé oddelenie zobraz priemerný plat a počet zamestnancov, ale len pre oddelenia s priemerným platom nad 1500.›
SELECT o.nazov AS oddelenie,
       COUNT(z.id) AS pocet,
       AVG(z.plat) AS priemerny_plat
FROM Oddelenia o
LEFT JOIN Zamestnanci z ON z.id_oddelenie = o.id
GROUP BY o.id, o.nazov
HAVING AVG(z.plat) > 1500
ORDER BY priemerny_plat DESC;

Vysvetlenie:

  • LEFT JOIN — aj prázdne oddelenia (bez zamestnancov) by sa zobrazili, ale po HAVING ich pravdepodobne odfiltrujeme.
  • GROUP BY o.id, o.nazov — zoskupíme podľa oddelení.
  • HAVING AVG(z.plat) > 1500 — filter na skupinách (nie WHERE, lebo používame agregačnú funkciu).
  • ORDER BY — usporiadanie výsledku.
Q29.Daná tabuľka Sklad(nazov, vyrobca, telefon_vyrobcu, cena, mnozstvo) s PK(nazov, vyrobca). V akej je NF a ako ju normalizujete?›

Analýza:

  • 1NF — OK (atomické hodnoty, PK existuje, žiadne opakujúce sa atribúty).
  • 2NF — NIE. Atribút telefon_vyrobcu závisí len od časti PK — vyrobca, nie od celého zloženého PK (nazov + vyrobca). Cena a množstvo závisia od celého PK.

Anomálie: ak vymažeme všetky výrobky od jedného výrobcu (napr. všetky Milka výrobky), stratíme aj jeho telefónne číslo.

Riešenie — rozdelenie tabuľky:

Sklad(nazov PK, vyrobca_id FK, cena, mnozstvo)
Vyrobca(vyrobca_id PK, nazov_vyrobcu, telefon)

Obe tabuľky teraz vyhovujú 2NF aj 3NF (žiadne tranzitívne závislosti).

Q30.V chemickej továrni potrebujú jeden integrovaný riadiaci systém pre celý závod — desiatky reaktorov, miešačov, kotlov v jednej budove. Aký systém zvolíte a prečo?›

Vhodný je DCS (Distributed Control System).

Dôvody:

  • DCS je určený pre riadenie technologických procesov v rámci jedného závodu.
  • Distribuované riadenie realizované priamo v riadiacich staniciach systému.
  • Vhodný pre komplexné procesy s mnohými regulačnými slučkami (typické v chémii, petrochémii).
  • Integrované riadenie + vizualizácia + alarmy + history na jednej platforme.
  • Vysoká spoľahlivosť a redundancia.

SCADA by bola nevhodná, lebo nie je primárne určená na komplexné regulačné slučky v jednom závode (skôr na geograficky rozľahlé systémy).
